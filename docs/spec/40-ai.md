# 40: AI

`src/ai/` implements `Decider` (`00-architecture` §11). It reads only the engine's public API (`view`, `legalActions`,
`validate`, `query.*`) and never mutates state. It runs in a Web Worker in the browser and in-process in
`npm run sim` / `npm run bench:ai`. AI randomness uses `hash(gameSeed, decisionId, tier)`, never `state.rng`.

## 2. Utility decider and activation ordering

Each decision: build candidates → filter by `validate` → apply hard constraints (§6) → score → pick max
(tie-break by AI seed). `legalActions` is the fallback pool; the AI never returns an action outside it unless it
passes `validate` (continuous moves).

**Turn plan** (computed at the first `chooseActivation` of a turn, refreshed after every activation):

| Order | Bucket | Examples |
|---|---|---|
| 0 | assassination script, if committed (§7) | its activations in planned order |
| 1 | enablers | caster spells/feat that buff others, focus-dependent setups; caster goes first only if it buffs, else last |
| 2 | shooters and AOE | clear screens, remove contesters |
| 3 | chargers and power attacks | melee into weakened targets |
| 4 | scenario movers | claim/contest elements, avoid kill box |
| 5 | rest | |

Move candidates (`moves.ts`, ≤64): stay; rings at 50% / 100% of allowed distance × 16 angles; points toward each
objective, best target, nearest cover/concealment edge, behind the nearest wall from the threat map's hottest
direction; charge lanes for each target in LOS. Units: candidate for the moved trooper, then a validated chain
placement for the rest.

Score (weights per tier, `tiers.ts`):
`U = wD·E[damage value] + wK·Σ pKill·value(target) + wS·ΔVP_expected + wC·Δcontrol − wT·threatExposure − wL·leaderRisk`
- `value(model)` = points cost × role factor (war-engine 1.2, caster ∞ via assassination, unit per trooper).
- `ΔVP_expected` uses `query.control` on the hypothetical end positions.

## 3. Closed-form dice math (`prob.ts`)

Exact enumeration over `n` d6 (n ≤ 4, ≤1296 outcomes), memoised by `(n, need)`.

**Attack** (need = DEF − (stat + mods)): hit iff Σdice ≥ need, except all 1s always miss and all 6s always hit when
n ≥ 2. Crit = direct hit with any two dice matching (R1.5, p84). Attack dice reduced to 0 = auto-miss. Auto-hit / auto-miss from
state short-circuit (`rollAnyway` only changes crit odds).

| n | count of outcomes with Σ ≥ t (of 6ⁿ) |
|---|---|
| 2d6 (/36) | t=2:36 3:35 4:33 5:30 6:26 7:21 8:15 9:10 10:6 11:3 12:1 |
| 3d6 (/216) | t=3:216 4:215 5:212 6:206 7:196 8:181 9:160 10:135 11:108 12:81 13:56 14:35 15:20 16:10 17:4 18:1 |

Then clamp: 2d6 `pHit ∈ [1/36, 35/36]`; 3d6 `[1/216, 215/216]`.

**Damage** per hit: `D = max(0, Σk d6 + POW − ARM)`, k = 2, +1 boost (focus or charge auto-boost; never both on one
roll), −1 for Resistance to the damage type, −1 for a crippled weapon location, min 1 die.
Per-attack distribution: `P(D=0) += 1 − pHit`; `P(D=d) += pHit · P(dmg = d)`.

**Sequences.** Total damage = convolution of per-attack distributions, truncated at remaining boxes `H`.
`pKill = P(ΣD ≥ H)`. This holds for **grids too**: spill wraps 6 → 1, so a war-engine is disabled exactly when total
boxes filled ≥ remaining boxes.
- Knockdown chains (a hit that knocks down makes later melee auto-hit): 2-state Markov chain {standing, down}.
- **Tough**: on reaching H, with p = 1/3 return to H−1 and set down; chain continues for later attacks.
- **Power Field**: the defender's caster reserve `F` reduces the first `F` positive damage instances by 5 each
  (greedy, worst case for the attacker). Exact enough for planning; flagged in bench output.
- **Crippling** (grids): exact for one attack (6 columns × damage values against the current grid fill); for
  sequences, 256 seeded sample paths from the AI rng.
- Blast and spray: per-model independent rolls; AOE blast uses `blastPow` on the N closest (engine `query` lists them).

## 4. Focus knapsack (`focus.ts`)

Multiple-choice knapsack over integer focus `F` (caster ARC ≤ ~8; each war-engine ≤ 3).

| Group | Options (cost) | Value |
|---|---|---|
| each planned attack | none (0), boost hit (1), boost damage (1), both (2) | Δ E[damage value] + Δ pKill·value |
| additional attacks | k extra (k) | marginal value of the k-th attack |
| each spell | skip (0), cast (COST) | spell value model per effect op |
| each war-engine allocation | 0..3 (0..3) | best value of that engine's own knapsack with k focus, incl. run/charge/power-attack 1-focus costs |
| upkeeps | drop (0), keep (1) | remaining value of the effect |
| Power Field reserve | 0..F (r) | −Δ leaderRisk(r) from §6 |
| heal | 0..n (n) | −Δ leaderRisk |

DP `O(groups × F × options)`; solved at `allocateFocus`, at each attack's `boost*` decision (re-solved with fresh state)
and at caster decisions. Ties prefer keeping focus.

## 5. Threat maps (`threat.ts`)

- 0.5" grid over the table, rebuilt at turn start, patched for models that moved.
- Per enemy model: melee reach = SPD + 3 + weapon range (1 or 2) from its base edge if it may charge (war-engines:
  assume focus if inside caster CTRL); ranged reach = SPD + RNG; caster spells = SPD + spell RNG, or arc node position
  + RNG; power attacks (slam SPD + 3, trample) for war-engines; flags for feats not yet used.
- Each cell stores per enemy: reachable-by-kind and expected damage vs three reference profiles (trooper,
  war-engine, own caster) via §3, plus `maxPKill` vs our caster given its current focus.
- `query.threat` (engine) supplies the reach numbers; the AI only adds the probability layer.

## 6. Caster safety: a hard constraint

- For any candidate that moves our Leader or spends its focus (including `allocateFocus`), compute
  `leaderRisk = pKill(our Leader next enemy turn)` by running §7 from the opponent's side with the Leader's end
  position and retained focus (Power Field reserve).
- Candidates with `leaderRisk > τ_safe` are removed **before** scoring. If none remain, pick min `leaderRisk`.
- Also forbidden: ending the Leader's turn inside the Kill Box when it scores, and stepping into a known
  assassination lane when an equal-utility safe square exists.

## 7. Assassination search (`assassin.ts`), every turn

1. Contributors = our models whose threat reaches the enemy Leader this turn (§5).
2. For each, options: charge (lane checked with `query.moveCheck`, screens block), ranged, spells (direct/channelled),
   power attacks; each yields a damage distribution vs the Leader incl. its Power Field reserve and Tough.
3. Beam search (width 16, depth ≤ 8 contributors) over order + option + focus allocation; prune lanes blocked by
   models that activate earlier only if that earlier model clears them (e.g. a kill on the screen).
4. `pKill` of the best line ≥ `τ_go` → commit: the line becomes the turn plan's bucket 0 and biases target choice.
   Recompute after each step; abort the script if pKill drops below `τ_abort`.
5. Same search from the enemy side feeds §6.

## 8. Tiers

| Tier | Policy | τ_safe | τ_go | Extras |
|---|---|---|---|---|
| `random` | uniform over `legalActions` (moves: random sampled candidate) | none | none | always answers; used for sim/fuzz |
| `easy` | greedy utility, score noise σ = 15%, no knapsack (boost if pHit < 60%), no assassination search | 0.40 | none | keeps 1 focus on Leader |
| `normal` | full: plan, knapsack, threat map, assassination search | 0.15 | 0.50 (0.35 when behind on VP in round ≥5) | |
| `hard` (M9+) | normal + 1-ply opponent reply on top-8 candidates | 0.10 | 0.45 | |

## 9. Bench (`npm run bench:ai`)

`tsx tools/ai-bench.ts --pair normal:easy --games 200 --seed s` → `tools/out/bench-<date>.json` and a 10-line summary.

| Metric | Target |
|---|---|
| win rate normal vs easy / easy vs random / normal vs random | ≥70% / ≥85% / ≥95% |
| win type split | assassination / scenario / round-7 tiebreak |
| own Leader lost per game | normal < 0.25 vs easy |
| assassination lines found (pKill ≥ τ_go) vs converted | conversion ≥ predicted pKill − 10 pts |
| decision time p50 / p95 / max (per kind) | ≤50 / ≤500 / ≤2000 ms |
| rejected actions, stalls, decision-cap hits | 0 |
| predicted vs actual damage (calibration) | mean error < 0.5 boxes per attack |

## 10. Web Worker

- `src/ai/worker.ts`, module worker created with `new Worker(new URL('./worker.ts', import.meta.url), {type:'module'})`.
- Messages: `init {bundle, tier}` → `ready`; `decide {view, pending, legal, seed}` → `action {action, trace?}`.
  `trace` (debug) carries the top-3 candidates with scores for the `?test=1` overlay.
- The engine + data chunk loads inside the worker once.
- Client timeout 2 s per decision → falls back to `legal[0]` (or the easy policy on the main thread if fast) and logs.
- The bot only receives a decision when presentation is idle (`50-client` §2).
